# Prompt Builder

사용자의 한 줄 요청을 받아, 다른 Claude Code 세션(또는 서브에이전트)에 그대로 넘길 수 있는 **구조화된 작업 지시서**를 생성한다. lane4 작업 히스토리와 컨벤션을 자동으로 수집해 초안을 채우고, 비어있는 부분만 질문으로 보완한다.

## 핵심 제약사항

- **코드를 수정하지 않는다.** 프롬프트(지시서) 문서 생성만 수행한다.
- **추측으로 배경을 채우지 않는다.** 히스토리/코드에서 확인된 사실만 쓰고, 불명확하면 질문한다.
- **질문은 한 번에 하나씩** 한다. 자동 수집으로 이미 채워진 항목은 재질문하지 않고 "이거 맞지?" 확인만 한다.
- 출력 형식은 `references/prompt-template.md`를 따른다.
- lane4 중심 작업을 가정하되, lane4와 무관한 요청이면 컨텍스트 수집 단계를 가볍게 건너뛴다.

## 워크플로우

### 1. 의도 접수
사용자의 요청 한 줄을 받는다 (예: "배차 말일 버그 후속 SQL 짜는 프롬프트 만들어줘"). 요청이 너무 막연하면 이 시점에서 "무슨 작업을 시키려는 건지" 한 가지만 먼저 확인한다.

### 2. 자동 컨텍스트 수집 (병렬 서브에이전트)
아래 두 에이전트를 **한 메시지에서 병렬로** 디스패치해 관련 맥락을 끌어온다. 메인 컨텍스트를 아끼기 위해 반드시 위임한다.

- `lane4-history-researcher` — 요청과 관련된 과거 유사 작업을 `~/IdeaProjects/claudedocs/history/`, git log, memory에서 검색. 관련 history 문서 파일명과 한 줄 요약을 받는다.
- `lane4-context-loader` — 관련 CLAUDE.md 섹션, lane4 컨벤션, 관련 프로젝트/최근 커밋을 끌어온다.

결과를 요약해 템플릿의 **Context(배경·참고 컨벤션)** 초안으로 채운다. lane4 무관 요청이면 이 단계를 생략한다.

### 3. 갭 분석 & 질문
좋은 Claude Code 지시서에 필요한 6요소를 점검하고, **자동 수집으로 채워지지 않은 것만** 하나씩 질문한다.

| # | 요소 | 템플릿 위치 | 자동 수집 가능? |
|---|------|-------------|-----------------|
| ① | 목표·왜 | Context | 요청에서 일부, 부족하면 질문 |
| ② | 대상 프로젝트/파일 | Context | context-loader 힌트, 확정은 질문 |
| ③ | 작업 내용(구체 지시) | Task | 사용자 요청 기반, 단계화는 질문 |
| ④ | 완료 조건/수용 기준 | Task > 완료 조건 | 거의 항상 질문 |
| ⑤ | 참조 과거작업·코드 | Context > 배경 | history-researcher가 채움 |
| ⑥ | 추천 스킬/에이전트 | Constraints | 스킬이 판단해 제안 |

- 이미 아는 항목은 확인만, 모르는 것만 새로 묻는다.
- 한 번에 하나의 질문만 던진다.

### 4. 지시서 조립 & 확인
`references/prompt-template.md` 형식으로 지시서를 조립해 채팅에 전체를 보여주고 승인받는다. 수정 요청이 있으면 반영 후 다시 보여준다.

### 5. 저장
승인되면 아래 경로에 저장한다.

- 경로: `~/IdeaProjects/claudedocs/prompt {YYYY-MM-DD}_{제목}.md`
  - 날짜는 오늘 날짜(YYYY-MM-DD).
  - `{제목}`은 핵심 키워드 2~4개로 짧게. 공백보다 하이픈 권장, 한글 가능 (예: `prompt 2026-07-21_배차-말일-후속-sql.md`).
  - claudedocs 볼트 **루트**에 저장한다.
- 저장 후 파일 경로 1줄과, 사용자가 바로 복사해 쓸 수 있도록 지시서 본문도 함께 안내한다.
